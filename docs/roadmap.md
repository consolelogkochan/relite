# ロードマップ

- **用途**：ReLite の予定のカード。構想の `docs/concept.md` と合わせて企画書として読む。カードは作る段で分けたり足したりし、見直しながら育てる
- **書かないもの**：アカウントや鍵の守り方、サーバーの IP アドレスやアカウントの ID などの伏せる値、個人の名前、前のアプリの弱点（今も公開しているため）。このファイルは公開される
- 決めた経緯は `docs/decisions.md` の「1-3 ロードマップ」の項にある。持ち越しの項目は `docs/ledger.md` の、カードごとの小節にある

## 並べる基準

アプリをほぼ最初から作るので、どの判断と土台を先に置けば後のカードが手戻りしないかで並べた。

- 後から変えたら響く範囲が大きいものを先に
- ほかのものが前提にしているものを先に
- 早く作れば早く分かる危険があるものを先に

**認証と認可を分ける。** 認証（誰か。ログインID で要求の主を見分ける）は、すべてのテーブルが前提にするので先に作る。認可（何をしてよいか）は、まとめて後で作らず、機能を作るカードごとに、その機能の分を一緒に作る。認可を最後にまとめて作ると抜け漏れが生じるリスクが増え、認可の細部は既存の機能を前提にしなければ決められないため。

## 各カードの進め方（コードを作るカード）

- **始め**：Claude Code が前のアプリ（project-lite）の、その機能と画面を洗い出し、前のコードを参照して「どこをどう変えるか」の判断の材料を出す。人と対話AI がその判断を決める
- **粒度**：学習のために、1枚のカードで扱う新しい概念を1〜2個までにする
- **実装の報告**：変えた部分ごとに「前のコードではどう作っていたか／今回どう変えたか／なぜ変えたか」を1〜3行で書く。始めの判断と組にして、統一ログに入れる
- **振り返り**：人が自分で調べて言語化したものを、振り返りの中で出してもらい、対話AI がレビューして統一ログに入れる。新しい工程にはしない
- **欠点指摘**：Claude Code が `docs/review-criteria.md` の基準でコードを走査してから、対話AI が欠点を指摘する。欠点が見つかるたびに、同じ形の欠点を見つける基準として1行足すかを、人と対話AI で決める
