# 判断と経緯

- **用途**：このプロジェクトで、何を、なぜ、いつ決め、何を確かめたかの原本。経緯は書き換えず、日付を添えて足す
- **書かないもの**：アカウントや鍵の守り方、サーバーの IP アドレスやアカウントの ID などの伏せる値、個人の名前。このファイルは公開される
- 各項には、根拠の種別（人が述べた・実測・出典・推測。推測なら誰の推測か）を添える

## 1-1 構想（2026-11-18）

| 決めたこと | 根拠の種別 |
| --- | --- |
| このカードの的は、カテゴリを「境界の設計」とし、問いを「利用者を何で見分け、アプリの外（メール・外の AI）とどこで線を引くか」とした。選んだ理由：このカードで下す判断の多く（メールの登録をやめる、通知をメールと切り離す、共有の相手を何で探す、外の AI に操作させる）が、この問いに依存している。利用者の見分け方はデータの作りに入るので、誤ったときに戻しにくい | 人と対話AI の合意 |
| このカードの範囲は、構想（誰に・なぜ・何を）と、機能の一覧（今の機能を1行ずつ並べ、残す・変える・捨てる・未定を決める）とする。置き場所は `docs/concept.md`。2時間に収まらなければ、一覧で決めるところを次のカードに分ける | 人と対話AI の合意 |
| 基本は、既存の機能を残しつつ磨く。メールアドレスの登録は不要にする。そのほかの取捨選択は、一覧を作って網羅的に判断する | 人が述べた |
| SPA にする。理由：今のアプリがページを読み込み直さないのは、ページの読み込みの体験の悪さを無理に避けたためで、SPA にすれば、カードの登録や変更、ドラッグ＆ドロップによる描き直しと相性が良い。今の作りの拙さは、設計がうまくできていなかったところが大きい（AI との協働も拙かった） | 人が述べた |
| タイムラインは、有料のライセンスが要らない、無料の部品で作る。そのために機能の取捨選択が要れば行う | 人が述べた |
| 前のアプリの点検で見つかったことの一部は、後回しにした。前のアプリは、ReLite ができたら閉じる見込み | 人が述べた |
| 今の3つの表示（Kanban・カレンダー・タイムライン）の不安定さには、作りの側の原因（1つの大きな部品にすべてが入っていること、ドロップの後に一覧を空にして描き直していること、絞り込んだ後の番号でドロップの位置を決めていること、送る方式と受ける方式のずれ）が関わっている見込みがある。表示を作るカードで扱う | 推測（対話AI）。確かめていない |
